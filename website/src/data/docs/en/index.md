Vezuna brings household profiles, laboratory reports, medication schedules, and exports into one on-device app. These guides distinguish everyday use from native development.

> **Release preparation:** no stable release has been published. Signed store builds, production model delivery, physical-device checks, and store review remain open. Vezuna organizes records; it does not diagnose conditions, recommend treatment, or change doses.

## Using Vezuna

- [Getting started](/docs/getting-started): create a fictional first profile, import a report, and understand app identity.
- [Laboratory records](/docs/lab-records): import images and PDFs, correct OCR drafts, confirm results, and compare values.
- [Medications, reminders, and exports](/docs/medications-reminders-exports): record schedules and prepare PDF or CSV copies.
- [Privacy and data](/docs/privacy-and-data): permissions, local storage, sharing, backups, and deletion.
- [Offline models](/docs/offline-models): current model-delivery limits and local AI boundaries.

## Developer guide

[Build, test, and release](/docs/developers) covers the repository structure, native setup, synthetic checks, localization, branding, model provenance, contribution rules, and EAS submission of externally built signed binaries.

## Support

Use [GitHub issues](https://github.com/bloodf/vezuna/issues) for general or privacy questions. Use the repository’s **Security → Report a vulnerability** channel for security reports. Never attach real medical records, prescriptions, personal screenshots, vault files, or backups. Use synthetic examples only. See [Support](/support).
