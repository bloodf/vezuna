# Isolated Android delivery-test variant

`localPad` inherits debug behavior and installs as `app.vezuna.padtest`, with a visible test label in English, Portuguese and Spanish. The normal debug/release application ID remains `app.vezuna`. The existing FileProvider authority derives from the application ID, so this variant uses `app.vezuna.padtest.files`.

This variant explicitly uses a blank LVL key together with the existing debug-only premium bypass. It is only for local bundletool delivery tests; it does not test real Play licensing. Release keeps its original LVL key configuration and `DEBUG_PREMIUM_BYPASS=false`. Never upload this debug variant to a store.

Build `:composeApp:assembleLocalPad` for package/manifest inspection. Once the asset-pack module is integrated, use `:composeApp:bundleLocalPad` with the explicit verified model inputs documented in the asset-pack change. Keep the existing build semaphore, required Java/SDK and disk floor. No model download, catalog entry or inference is implied by selecting this variant.

Before any device installation, inspect the exact APK/APKS manifest and signing identity, confirm the intended test-package identity and an exclusive phone lease, and verify that the test installation has a distinct UID and data directory. A suffix in source alone is not runtime isolation proof. Use synthetic records only. Never uninstall or clear `app.vezuna` for local delivery testing. Any replacement/cleanup of the disposable test installation remains a separately scoped device operation.

Successful local delivery is separate from Play-served delivery, real license verification, model memory/quality/safety acceptance and native runtime obligations. This variant does not waive those release requirements.

## Deadlines, evidence and measurement

One monotonic deadline starts at method entry and ends after 900 seconds. Work stages stop at 780 seconds, reserving 120 seconds within the global cap for final unload, failure reconciliation and sampler join. The successful lifecycle requires all delivery, copy, load and unload boundary samples. Failure cleanup prioritizes a joined unload without waiting on an already failed sampler. Every stage maximum is capped by the remaining global budget. Preflight is at most 60 seconds, host acknowledgement 30, delivery 180, verified copy 180, identity verification and each load 120, each generation 60 and each unload 60. Those maxima cannot all be consumed in one run. Expiration fails the sequence without retries, reduced settings, omitted cases or extension.

The controller waits for actual worker-thread return. On a deadline it requests cooperative cancellation on a separate thread and allows at most ten seconds of reconciliation within the global deadline. A late return remains a failure. It queues no successor or unload after an unresolved worker or cancellation signal. `TEARDOWN_UNRESOLVED` retains process and device ownership. Coroutine timeout, cancellation, a daemon thread or a host-command timeout does not bound or prove native exit. OS I/O and native cancellation can also block. The independent host watchdog described below is mandatory.

A separate finite sampler targets one-second cadence without periodic catch-up. It records actual monotonic read start/end, duration, start-to-start gaps, process UID/PID/start ticks and stage-boundary snapshots. Delivery, verified copy, both loads and both unloads have boundary samples. Boundary reads have bounded controller waits and are never called in native generation callbacks. Required sample/read failures fail measurement. Periodic samples can miss short phases and all observed peaks are lower bounds.

System total RAM, available RAM and pressure threshold use bytes from one `ActivityManager.MemoryInfo` call per sample, alongside `lowMemory`. PSS uses `Debug.getMemoryInfo.totalPss`, KiB multiplied by 1024. Its refresh/rate limits and freshness are `UNKNOWN`; repeated values do not prove fresh one-second PSS. RSS comes from `/proc/self/status` `VmRSS`; Linux `kB` means KiB and is multiplied by 1024. Native heap uses `Debug.getNativeHeapAllocatedSize` bytes and describes allocator accounting. It does not include every mapping or prove resident model size. Missing RSS and unsupported mmap virtual size remain `UNKNOWN`; no native84 acceptance follows. Sampling cost and actual gaps include contention, and log persistence adds overhead beyond the recorded metric-read duration.

Each run requires a new `noBackupFilesDir/local-pad-research/<runId>` directory. It retains JSONL events, exact synthetic prompts and seven full synthetic UTF-8 outputs. Event storage is capped at 8 MiB and each output at 1 MiB, at most 15 MiB total plus the bounded host acknowledgement. Any overflow or write error fails the run. A partial output remains preserved and explicitly incomplete; it is never silently truncated into a passing answer. Primary and teardown errors remain linked through suppressed exceptions and event records, with logcat/stderr fallback if evidence storage fails. Generation callbacks perform no metrics reads or log flushing. First partial means a nonempty chunk seen by the collector, not a native first-token timestamp. Text length is no token-count or effective-context measurement.
